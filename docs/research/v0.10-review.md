# context-builder — Post-v0.9.0 Review

> **Generated:** 2026-08-31, against `master` @ `7e4dce4` (v0.9.0). Every finding below was verified against live source, and the behavioural ones were reproduced by running the built binary. Dependency upgrades marked "verified" were applied to the manifest, compiled, and run through the full test suite before being reverted.

**Baseline health: good.** `cargo build --all-features`, `cargo clippy --all-targets --all-features` (clean, no warnings) and `cargo test --all-features -- --test-threads=1` (**379 tests, 0 failures**) all pass on rustc 1.94.1. v0.9.0 landed the bulk of the "Trustworthy Output" roadmap: token budgeting now uses the real tokenizer, `--encoding` is selectable, `-o -` pipes to stdout, the cache writes atomically, `fs2` is gone, and a long list of tree-sitter extraction bugs is fixed.

What follows is what v0.9.0 **did not** close, plus what has drifted since.

---

## 1. Advertised features that still do nothing

These are the highest-value items because the tool's stated identity is accuracy, and each one is a documented flag that silently no-ops.

### 1.1 `--truncate` is completely inert (both modes)

`find_smart_truncation_point` (`src/tree_sitter/mod.rs:86`) still has **zero production callers** — v0.9.0 fixed its char-boundary panic (B19) but never wired it up. The renderer says so in a comment:

```
src/markdown.rs:619
// Note: Smart truncation (`truncate: "smart"`) indicates AST-boundary
// truncation should be preferred when content needs truncating.
// Without a per-file max_tokens budget, no truncation is applied.
// The flag is stored for future use when per-file token limits are implemented.
```

`ts_config.truncate` is consumed at exactly one place in the whole renderer — `markdown.rs:113`, where it is folded into the content hash. Reproduced:

```
$ context-builder -d fixture -o - -f rs --max-tokens 200 --truncate smart | tail -3
_⚠️ Token budget (200) reached. 1 remaining files omitted._
$ context-builder -d fixture -o - -f rs --max-tokens 200 --truncate byte | tail -3
_⚠️ Token budget (200) reached. 1 remaining files omitted._
```

Byte-identical. Over-budget files are **omitted**, never truncated — so `--truncate smart` vs `--truncate byte` is a distinction without a difference, and README:268 ("Files are truncated/skipped when exceeded") is half true.

**Fix:** in the budget branch of `process_file`, when a file would exceed the remaining budget, truncate it to the remaining allowance instead of dropping it — `smart` via `find_smart_truncation_point`, `byte` via the char-boundary clamp — and emit a per-file "truncated" marker. This is roadmap F5, still the single biggest credibility gap.

### 1.2 `--visibility` is a no-op for 5 of 8 languages

v0.9.0 fixed Java (B12) but B12 also covered C++, and that half was not done. `cpp.rs:212` is unchanged:

```rust
fn get_visibility(&self, _node: &tree_sitter::Node) -> Visibility {
    // C++ has access specifiers: public, private, protected
    // For simplicity, we check sibling nodes for access specifiers
    // This is a simplified check; full implementation would track class context
    Visibility::All
}
```

Auditing all eight extractors for any `visibility ==` / `get_visibility` filtering:

| Language | `--visibility` filtering | Notes |
|---|---|---|
| Rust | ✅ implemented | incl. `pub(crate)` tiering (v0.9.0) |
| Go | ✅ implemented | exported = capitalized identifier |
| Java | ✅ implemented | `modifiers` scan + implicit-public interface members (v0.9.0) |
| **C++** | ❌ stub returns `All` | access specifiers ignored |
| **C** | ❌ no filtering at all | `static` = internal linkage is the natural mapping |
| **Python** | ❌ no filtering at all | `_`/`__` prefix convention |
| **JavaScript** | ❌ no filtering at all | `#private` fields, `export` |
| **TypeScript** | ❌ no filtering at all | explicit `private`/`protected`/`public` |

Reproduced on Python — `--visibility public` leaks every underscore-private symbol:

```
$ context-builder -d fixture -o - --signatures --visibility public -f py
```
```python
// Functions
def public_fn(x):
def _private_fn(y):     ← should be filtered
// Structs/Classes
class C
// Functions
def _hidden(self):      ← should be filtered
```

README:278 documents `--visibility` with no language caveat. **Fix:** implement the five missing extractors (TypeScript is the easiest and highest-value — the modifier is explicit in the grammar), or at minimum warn when `--visibility` is passed for a language that ignores it.

### 1.3 TypeScript class members are not extracted at all

The same run surfaced a second bug: for `export class K { public open(): void {} private secret(): void {} }`, `--signatures` emits only

```typescript
// Structs/Classes
class K
```

Neither method appears. Class bodies are the majority of real TypeScript code, so `--signatures` on a TS codebase is currently near-empty. `typescript.rs` (634 lines) walks top-level declarations but does not descend into `class_body` for `method_definition`. This is a straightforward extractor gap and probably the highest output-quality-per-hour fix in the tree-sitter subsystem.

## 2. Correctness drift: three copies of the extension→language map

There are three independent `match extension` language maps, and they have already diverged:

| Site | Purpose | Handles `mjs`/`cjs`? | Handles `jsx`/`sql`/`sh`? |
|---|---|---|---|
| `markdown.rs:402` | code-fence language for file bodies | ❌ | ✅ |
| `markdown.rs:677` | language passed to the signature formatter | ✅ | ❌ |
| `lib.rs:803` | code-fence language in the **auto-diff** path | ❌ | ❌ |

Observable consequence — the same file gets a different fence in the body than in its signature block:

```
$ context-builder -d fixture -o - -f mjs -f py
### File: `m.mjs`
```mjs            ← not a highlightable language; markdown.rs:677 would have said `javascript`
```

And a `.jsx` or `.sh` file rendered through the auto-diff path (`lib.rs:803`) gets a raw-extension fence while the same file in a normal run gets `jsx`/`bash`. **Fix:** one `pub fn language_for_extension(ext: &str) -> &str` in a single module, called from all three sites. Roadmap F3 already flagged this as a prerequisite for a format-renderer trait; it is worth doing on its own.

## 5. Documentation drift

- **`SKILL.md:160`** still documents `--truncate` as `smart` or **`simple`**. `simple` has never been a real mode; the values are `smart`/`byte`. (README:277 was fixed in v0.9.0; SKILL.md was missed.)
- **`README.md:80` and `:277`** advertise "smart AST-boundary truncation" as a working feature — see §1.1. Either ship the wiring or soften the claim.
- **`README.md:268`** — "Files are truncated/skipped" — only skipping happens.
- **`README.md:278`** documents `--visibility` with no note that it is a no-op for C, C++, Python, JS and TS (§1.2).
- **`AGENTS.md`** is stale in three places: the tech-stack table still lists "**Caching** | JSON + `fs2` file locking" (fs2 was removed in v0.9.0), the project-structure tree omits `src/tree_sitter/` entirely (9 files, ~4.5 kLOC — 30% of the codebase), and the feature-flag table omits all nine `tree-sitter-*` features. The release process section still covers only `cargo publish`, not the tag-triggered binary release or the winget bump.
- **`README.md:95`** still promotes `curl … | bash`, which commit `87657bf` deliberately removed from SKILL.md over a VirusTotal flag. Pick one policy.

## 6. Structural / maintainability

Not urgent, but these are what will make the v0.10 strategic items (library API, MCP server) expensive if left alone:

- **`lib.rs` is 2609 lines**, of which `run_with_args` alone is ~590 (`lib.rs:66-658`). The auto-diff pipeline (`generate_markdown_with_diff`, `lib.rs:689-856`) is a near-parallel second rendering path — it has its own language map (§2), buffers the whole document in memory rather than streaming, and has to be point-patched in step with the main path every time either changes. Extracting `auto_diff.rs` and routing it through the same `impl Write` streaming renderer would retire that duplication class.
- **`markdown.rs` is 1759 lines** with the format hardwired into `process_file`/`write_text_content`. Introducing the `OutputFormat` trait (roadmap F3, still unshipped) is the natural place to also collapse the three language maps.
- `src/diff.rs:231` — in the `(Some(_old_content), None)` arm, `previous.get(&path).unwrap()` re-looks-up a value the match already bound. Safe, but the `unwrap()` is gratuitous; bind `old_content` in the pattern.

**Theme: "Honest signatures" — finish what v0.9.0 advertised, then extend.**

| Order | Item | Effort | Why first |
